# Release Notes - Selected Variant Promotion on the Product Page

**Date:** October 13, 2026
**Version:** 0.3.0
**Type:** Bug Fix
**Ticket:** LMM-144

---

## Overview

This release is the Hyvä half of LMM-144. On a configurable product page the installment badge always showed the parent product's Leanpay promotion, even when the selected variant has its own product-level promotion. The badge now shows the selected variant's promotion, with the parent's as fallback.

Requires **leanpay/payment 0.18.0 or newer**, which renders each variant's badge with that variant's promotion and resolves the variant in the AJAX fallback. The listing part of the same fix (LMM-151) ships entirely in the payment module.

---

## Problem Statement

The Hyvä installment script refreshed the badge on every price update, but only passed the amount. The badge HTML it received or requested was always resolved for the parent product, so a variant with its own vendor product code still showed the parent's terms.

---

## What's Fixed

- The script tracks the selected variant from `configurable-selection-changed` and uses that variant's pre-rendered badge while its price is shown
- When no pre-rendered badge matches the price, the AJAX request sends the product and variant IDs, and the cache is keyed by amount and variant, so two variants with the same price but different promotions no longer share a badge
- Responses from an earlier selection are discarded, so quick switching between variants always ends on the latest variant's badge
- The product ID is passed to the script as a data attribute instead of being printed into the JavaScript

---

## Technical Details

### Affected Components

- `view/frontend/templates/pricing/render/js/installment.phtml`

### Upgrade Notes

- Upgrade `leanpay/payment` to 0.18.0 or newer at the same time. With an older payment module the product page keeps showing the parent's promotion, without errors.
- Installations that track these modules as git submodules should confirm both submodules point at compatible versions, since composer constraints are not applied in that setup.
- No configuration changes are required.

---

## Compatibility

- Backward compatible
- No visual changes to the badge, only the promotion terms it shows
- Simple products and configurable products without variant promotions are unchanged
- Listings and Hyvä Checkout unchanged by this module

---

## Testing Recommendations

1. Configurable product where one variant has its own Leanpay vendor product code: selecting that variant shows its terms, other variants show the parent's terms
2. Same as 1 with variants of equal price: switching between them still swaps the terms
3. Switch variants quickly several times: the badge ends on the last selected variant
4. Page load without a selection: the parent's badge, and no extra installment request
5. Simple product page: badge unchanged
